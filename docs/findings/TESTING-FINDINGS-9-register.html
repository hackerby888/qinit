F213

A constant name is global, and the last declaration wins

critical55 rows red · 13 after part 1

Every read below is fully qualified, so C++ has nothing to disambiguate and clang's column is simply correct. The TypeScript backend returns the value of the last constant declared under that name — across namespaces, across enum types, and across kinds of declaration: an enum constant overwrites a file-scope constexpr of the same name. Qualification is the fix a developer reaches for when two declarations collide; here it is accepted and ignored.

F222

An overload set with default arguments dispatches to the wrong overload

highnew · round 7

Overload viability was decided by params.length !== callArguments.length. Each block’s binding wins inside it, and the file constant is visible again once both blocks close.

The second diagnostic names the cause; the first is the finding “Locals share one slot per name” is a fair statement of a design limit — the backend’s locals model is flat, so a block cannot introduce its own binding. Calling that a use-before-declaration means the block-local declaration is being hoisted over the whole entry body — which is precisely what C99 block scoping exists to prevent, and what the Solidity test it was ported from (scoping/c99_scoping_activation.sol) was written to pin down.

F204

An out-of-range shift diverges only when the count folds

low–medium5 rows red

x << n with n >= width is undefined behaviour in C++, so neither backend is wrong. What is reportable is that clang answers the same expression two different ways depending on whether it folds — and that testing under --compiler typescript therefore cannot predict the on-chain answer. 

uint64 value = 1, count = 254
                     folded count   runtime count   self-consistent
TypeScript                  2^62            2^62   yes
clang                          0            2^62   no

2^62 is 1 << (254 mod 64) — what wasm's i64.shl does; it masks the count to six bits.
in-range controls agree everywhere: foldedInRange = runtimeInRange = 8 on both.

The width sweep bounds it: of 16 ShiftRhsWiderThanLhs variants, the ones that diverge are exactly the 32- and 64-bit widths with constSource=constexpr. Narrower widths agree because integer promotion widens them to int first. Without the constSource axis this would have looked like an ordinary width-dependent difference.

Confirmed on core’s own runtime Round 6 ran both artifacts under core’s WAMR host, which reproduces each backend’s row exactly. clang’s self-inconsistency is real on the production runtime, not a folding artefact of the test harness.

Seven defects in the harness and the engine recorded because an unrecorded generator bug looks like a compiler finding the next time someone reads the scoreboard

F219

The parity sweep compared one artifact with itself

buildContractWithClang and buildContractWithTypeScript both write <outDir>/<contractName>.wasm, and the sweep passed both the same directory. The TypeScript build ran second, overwrote clang’s artifact, and the run loop then read that one file twice — once labelled clang, once typescript. Round 6’s parity table therefore describes the TypeScript artifact twice, and real clang coverage under the third oracle was zero. Three confirmations: 357 of the 385 both-built contracts produced byte-identical rows, the 28 exceptions being the ones where the TypeScript build was refused and never wrote a file; and AccountBookWithIterationOrder’s clang artifact imports zero unregistered natives yet was scored shim-trap, a verdict that branch cannot reach. The part worth dwelling on is the validation. Round 6 offered “the shim-trap set is the same 76 contracts on each backend” as the check that made the run credible. But clang inlines KangarooTwelve into the module while the TypeScript backend imports it, so those sets should not have matched — their matching was the clearest possible evidence of the collision. A number was read as confirming the result when it was the disproof. fixed with per-backend output directories, plus a guard that aborts the sweep if two independently-produced artifacts are ever byte-identical — the condition that would have caught this on day one. Third defect in two rounds caught by a classification looking wrong, and the second caused by an artifact-path assumption; F218 was the first, one commit earlier.

F208

The simulator's committee is not reproducible between runs

qpi.computor(i) is generated per simulator instance, so a contract that stores qpi.computor(0) produces a different digest on every run — including two runs of the same backend, which is how it was caught. This is an engine defect, not a harness one. mitigated · the harness pins indices 0..675 before every run; it cannot pin more, because the override is keyed by raw index while the fallback wraps modulo committee size. Fixing it properly belongs in the engine.

F202

The nested-placement rewrite also rewrote the out-of-struct guard

placement=nested moves state members into an Inner struct and rewrites state.mut().X to state.mut().inner.X. Unconditionally — so it also rewrote placementGuard, the member that deliberately stays outside, which is the entire point of it. Thirteen contracts came back both-rejected, testing nothing. fixed with a negative lookahead · and it is this campaign's own evidence that two backends agreeing on a rejection tells you nothing about whether the contract was meant to be rejected

F206

The temporaries axis hoisted a function's locals into state

temporaries=stateScratch moves an entry's locals into a scratch sub-struct of StateData. Applied to a function, that makes a read-only entry write through state.mut(), which both build gates refuse — eleven contracts came back both-rejected. fixed · the axis now rewrites procedures only; the function variant renders identically and is dropped by the dedup

F207

entryOrder reordered entries whose types depend on each other

Where one entry's _locals names another entry's _input, declaring the contract's entries back to front emits the member before its type exists. Three ModifierAsPrivateFunction variants did exactly that. fixed · the axis stands down on such a dependency, and a corpus-wide control now walks every emitted contract asserting the invariant, so the next reordering axis cannot reintroduce it quietly

F218

The parity sweep manufactured 28 false divergences

It built its TypeScript side with the raw compileContractWithTypeScript driver, which skips the build gate. For a contract the gate refuses — F217’s block shadowing, the namespace alias — the raw driver returns an empty module rather than failing, and the sweep dutifully compared that empty module against WAMR and called the difference a divergence. Every one of the 28 read DEPLOY-FAILED(unexpected end of module) with zero imports. fixed by using buildContractWithTypeScript · and the difference is in acceptance, not codegen: for a contract the gate accepts, both paths emit byte-identical wasm. This is the exact trap F217’s notes describe, written one commit earlier, then walked into again in a different tool in the same round.

hostcalls/TimePackedDateAndTime advanced the simulator through an hour — about forty seconds per backend, and with four workers competing it exceeded the shard deadline. Worth recording because of what it looked like: a hang in the scoreboard is otherwise the signature of a compiler that does not terminate, which is exactly F210. fixed · the script now advances 240 ticks and crosses the same minute and hour boundaries; the re-run is clean at 0 hang

What the green rows are worth

The simulator, measured on both backends at last

Round 6’s version of this paragraph is withdrawn: F219 showed it had run the TypeScript artifact twice, so its clang column was never measured. Repaired and re-run, with the test shim widened from 5 natives to 20: across 105 contracts and 210 artifact runs, 195 agree, 0 disagree, 0 unreachable, and 15 refused by the TypeScript build gate. clang 105 agree — every contract built and ran — is the first real measurement of that backend against core’s runtime. The shim gap closed completely: 152 of 770 runs were unreachable before, 0 of 210 now. The sample is smaller than round 6’s 385, because the sweep was competing for four cores with the full differential run.

The oracle problem

Both backends share one build gate, one qpi.h, and one QubicSimulator. “6,514 matched” means they agreed with each other, not that they were right. F200, F213 and F204 run on core’s real WAMR host and reproduce their answers there, and round 7’s widened shim brings the hash-keyed and tick-reading contracts into range too. The rest still rest on the two backends disagreeing, and several cannot be settled this way — a compile refusal produces no artifact to run, and F220 lives in the asset region the shim deliberately does not cover.

The positive control

A suite that has never gone red is not evidence. Planting uint16: 2 → 4 in scalar-sizes.ts turned 126 of the 708 layout contracts red; restoring it returned all 708 to green. That also proves the compile cache's backend stamp, which would otherwise replay pre-mutation wasm and report a clean bill of health.

Stimulus coverage

So the green rows are not vacuous: the great majority of the 6,618 contracts move their state digest mid-script, and 357 make a cross-contract call. The ~179 hand-derived expect rows — 69 of them added this round, for DateAndTime and for HashMap removal — are the only assertions of correctness, and every one holds. They keep catching the author rather than the compiler: three of his errors in round 6, eleven in round 5, two more in round 7.

Not 6,091 trials

6,618 contracts from 449 archetypes is 14.7 variants each. Read the contract number as breadth of spellings. The variants earn their place as the axis bisector: when a mismatch appears, the sibling variants that differ in exactly one axis name the trigger — which is how F200 was pinned to sint32 and F204 to constSource=constexpr.

Only 2,780 are faithful ports

QPI has no revert, no uint256, no unbounded mapping and no reentrancy, so a Solidity test whose point was atomicity or 256-bit wraparound becomes a different test after porting. The corpus is a source of adversarial shapes, not evidence about Solidity semantics.

Where the remaining risk is

None of round 7’s four findings came from reading a big sweep’s red column. F219 came from a classification that looked wrong, F220 from reading the function that lowers a feature nobody had called, F221 from an archetype shipped without an expect row — and F222 from disproving the published root cause of F221, in a shape no archetype spells. The corpus’s real contribution was reproducing them across variants and showing F220 was not a fluke of one contract — worth having, but the finding rate per hour favoured reading the code over generating more of it. Two published root causes turned out to be wrong when someone finally built the fix, which is the sharpest argument on this page for building them. And the share-management API, where two earlier campaigns both found bugs, is still at zero call sites.
